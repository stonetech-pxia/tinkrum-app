# Decisions D-500 to D-599

One heading per decision: what was decided, why, and its status. The exact rules are in the code, its tests and `docs/agent/`. How this log is organized: [DECISIONS.md](../DECISIONS.md).

### D-500 — The README states three promises

The README now states three promises: no ads ever; the app is free, but Tink's model costs money, so a free quota comes first and a paid option may follow; and files and records on the phone are never uploaded. Not done: the beta-relay paragraph must return before a beta opens.

**Why:** The founder wants the README to say plainly why the project exists and what users can count on (2026-11-08).

**Status:** Decided

### D-501 — Convert to Word reads payslip-style tables: dark header bands, tables joined by a band, footers over the bottom line

Convert to Word now finds tables with dark header bands and tables stacked one under another, cutting the table at the new header, and reads a footer line as a table edge. Text outside a table's cells is written as a paragraph rather than dropped, and a barcode inside a ruled table is not cut out as an image. The edit page sets each column's width, so header cells no longer squeeze numbers.

**Why:** On 2026-11-08 the founder found a converted payslip much worse than a scanner app's, with its table lost.

**Status:** Provisional; not verified on a device

### D-502 — Convert to Word keeps a row's content together when a table is not recognized or is recognized wrongly

When no table is found, or a table may be wrong, Convert to Word writes one row per item, so an item and its amount stay together. Borderless columns far apart are joined only when the far column holds numbers lined up with text on the left. A ruled table whose column lines cut through words is not used as a table. Not done: splitting ruled rows whose columns sit on different lines. Changes D-471.

**Why:** On 2026-11-08 the founder said users want a usable Word with a sensible order, not a replica, since rules cannot cover every case.

**Status:** Provisional; not verified on a device

**Changed later by:** D-503, D-506.

### D-503 — Convert to Word: a two-column list no longer takes rows from a wider table, and a short summary under a table joins it

Word finds borderless tables in two passes: three-column tables first, then two-column label-and-amount lists only from the rows left over. A short summary under a three-column table can join that table. The founder asked for this on 2026-11-08 after receipt GST summaries were squeezed. Changes the rules of D-502.

**Why:** Measured on 67 labeled tables, the old rules squeezed or dropped receipt GST summaries and split a totals block.

**Status:** Provisional; not verified on a device

### D-506 — Convert to Excel finds tables without lines, and an invoice's totals no longer hide its item table

Convert to Excel now also finds tables without ruled lines, using the same rules as Word, so a text invoice comes out as a table. Word’s borderless finder no longer takes a totals block under the right-hand columns of an item table. Amends the shifted-number check of D-502. (The founder, 2026-11-09.)

**Why:** A clean text invoice came out of Excel as a few big cells, and Word garbled its table because a totals block looked like shifted amounts.

**Status:** Provisional; not verified on a device

### D-507 — Two save buttons that say where: "Save to Tinkrum" and "Save to phone"

The button that keeps a file inside the app is now “Save to Tinkrum”, and the one that copies it into a folder the user picks in Files is “Save to phone”. The desk’s Done sheet and File tab gain “Save to phone”, which asks for a folder each time. The founder asked for the two buttons to be clearly separated on 2026-11-09.

**Why:** A tester tapped “Save to files”, looked in the Files app and thought the file was lost.

**Status:** Decided; not verified on a device

### D-508 — When the camera can't be used, a run can take photos from the library this once

When a run’s photo step cannot use the camera, the error card offers “Choose photos instead”, which runs again using the photo library for that run only. The quick action’s own source is not changed, and “Run again” still uses the camera. The founder asked for this on 2026-11-09 after a scan stopped with no other way forward.

**Why:** Camera permission is often refused on a real phone, and the photos may already be in the library, so the user still wants the result.

**Status:** Decided; not verified on a device

### D-509 — Word and Excel files Tinkrum did not make can be opened and edited on the desk

(the founder, in conversation, 2026-11-09, relayed to a subagent: "do 2 with a subagent", item 2 being this; D-504 is the largest on main; for docx / xlsx this replaces D-362 item (10) and the system-preview-only rule of D-360 and D-470). ① `tool-office` reads them into the intermediate format, on the device, no network (`importOffice`; a small XML reader on fflate, no new runtime dependency). docx → DocDoc: paragraphs, bold, italic, underline and size per run, alignment, headings 1–2, lists (one per level, numbering continued), tables (merged cells, column widths), PNG / JPG / GIF / BMP pictures, page breaks; text boxes follow their paragraph, footnotes go to the end with [n] marks, tracked changes show as accepted. Dropped: headers and footers, comments, fonts, spacing, indents, highlight, strikethrough, super/subscript (text kept), page size (saved as A4), shapes, charts, SmartArt, EMF / WMF and web-linked pictures, letter numbering (becomes 1. 2.), per-word colors. xlsx → TableDoc: every worksheet as one table from A1, strings, numbers with value and number format (dates stay dates), merged cells, column widths, alignment; formulas keep their cached value and are saved as values. Dropped: fonts, fills, borders (saved without borders, `TableBlock.borderless`), row heights, comments, pictures, charts, validation. Password-protected, old .doc / .xls, broken and too large files (5,000 blocks, 20,000 cells, zip bombs) are not opened. ② The preview page shows the imported model (Word layout or table view, in memory); a password-protected file says so, also on "Edit". Putting it on the desk copies the original and imports the copy: the Word page editor or the table editor, not the PDF route; unreadable files go the old way. ③ Until edited the desk holds the original's copy (saving it saves the same bytes); after an edit writeDocx / writeXlsx rebuild it (`DeskSource.imported`); the first save or share on that desk shows one plain notice of what is not kept (Cancel saves nothing). The imported intermediate format is not stored next to the saved file; it is read again next time. Also fixed: an edited cell with a written number (`write`) kept the old number

**Why:** Users get Word and Excel files by email or from a computer and want to change them on the phone; the founder wants a usable document with a sensible order, tables and paragraphs rather than a replica (D-502). Provisional defaults, awaiting the founder: tracked changes accepted, footnotes moved to the end, headers and footers dropped, the notice once per desk

**Status:** Done; unit tests on real files (mammoth's Word files, a textutil docx from a UTF-8 page, a Pages docx with a password, jszip-built xlsx) and UI tests (`office-import-test.tsx`) pass, all fail on the old code; seen on the iOS simulator (Release build; English and French): a Word file and an Excel file from the Files app shown on the preview page, edited on the desk, saved after the notice (Cancel saves nothing), the original unchanged; a Pages docx with a password says so; not seen on a real device. Invariants: not touched (1, 2: read on the device, nothing sent; 4: the original is copied; 14: no second copy stored; 15: the preview writes nothing)

### D-510 — The file tools ship inside the app, and the intro says once what still downloads

(founder, in conversation, 2026-11-09, after a user test where three testers were surprised by the "Download file tools (50.8 MB)" dialog on their first file and by the on-device model prompt in New form, while the website and the intro said everything runs on the phone and works offline: do all three: bundle the common part, say it once at first launch, write it on the intro pages; the website is done separately). ① The packs D-456's one-time dialog offered come inside the app: text recognition `ppocr`, PDF preview `pdfview`, page flattening `dewarp`, layout `layout`, and on Android also the photo straightener `scan` (iOS finds paper edges itself) (`BUNDLED_PACKS` in `core/src/packs.ts`). `plugins/with-bundled-packs.js` downloads them at prebuild from the manifest's pinned URLs (cached in `node_modules/.cache/morph-bundled-packs`; the R2 ones need `EXPO_PUBLIC_MORPH_PACKS_URL` as in D-274 and are left out without it), checks size and SHA-256, and puts them under `packs/<id>/<version>/` (iOS: a folder in the .app; Android: APK assets); a failed download fails the prebuild. ② A pack that is in the app at the manifest's version counts as installed: the first time anything asks for it, it is copied to `documentDirectory/packs` with the same size and SHA-256 checks as a download (no network, no prompt) and `ready.json` marks it `bundled`. A copy that fails counts as not installed, and only a user-confirmed install then downloads it. A newer manifest version downloads the old way and replaces the copy. The root layout, text recognition and speech now share one `PackStore`, so two copies can't delete each other's files. ③ "Settings → Downloads" lists only downloaded packs and its hint says which tools come with the app; the scan and text recognition tool pages no longer say the first use downloads (new configs only: old configs keep their text, as with D-436); the quick-action line "The first run downloads what it needs" leaves out installed and bundled packs. D-456's dialog stays for builds without the packs and for later versions. ④ The first intro page (D-446), under "processed only on your phone", gets one small line (`guideIntro1Offline`), en: "File tools are built in and work offline. Extras, such as the on-device model that helps fill in forms (about 1.2 GB), download only when you first use them. Wi-Fi recommended." No new dialog; the empty home is unchanged. Still downloaded on first use: the on-device model (D-401), OCR language packs beyond PP-OCRv6, speech models, and system models (ML Kit, translation). Size ("before" is the same build with `packs/` taken out, the only binary difference): iOS Release .app (simulator) 273.5 → 324.9 MB (zipped 80.8 → 123.7 MB); Android release APK (arm64) 227.9 → 273.5 MB

**Why:** Testers read "runs on your phone, works offline" and then met a 50 MB download on their first file. The promise has to be true out of the box, and what still downloads has to be said before it happens. The packs are copied out once rather than read in place because Android assets are not files the ONNX runtime can open; on Android the copy costs about 60 MB more on the phone

**Status:** Decided by the founder (2026-11-09). Invariants: not touched (13 is now met for the file tools without a first download; 1: the copy stays on the phone). Unit tests fail on the old code (`pack-store-test.ts`, `file-bundle-test.tsx`, `packs-screen-test.tsx`, `workflow-journeys-test.tsx`, `guide-journeys-test.tsx` in en/zh/fr). Seen on the simulator (new "Tinkrum Downloads QA", iPhone 18 Pro, iOS 27, Release with the four variables), fresh install in English and French: the line shows on intro page 1 only; the first opened photo shows no download dialog and the four packs are copied with `bundled`; Convert to Word ran on the copied model; Settings → Downloads says "Nothing downloaded yet" with the new hint. Android compiled only (`compileDebugKotlin`, `assembleRelease`); not run on an emulator or a real device. The intro line was removed by D-592 (founder, 2026-11-19); the download prompt says the size, offline use and Wi-Fi

**Changed later by:** D-592.

### D-511 — Place text and signatures on a PDF at body-text size

Placing text or a signature on a PDF now works like a single tap. A tap on an empty spot while a text is selected only deselects it, new text starts at the finger, and its size follows the nearest recognized body line, or a default on pages with no text. A signature sits on the tapped line at a size set from that line. The founder asked for these fixes on 2026-11-09.

**Why:** The office-user tester needed about twenty steps to sign and date a contract and got stray copies and oversized text.

**Status:** Decided; not verified on a device

### D-512 — "Save to phone" counts as saved, and a quick second tap on "Next" no longer skips placing the signature

Once a desk’s files are saved into a folder the person picked, leaving without more changes no longer asks “Discard changes?”. On “Place signature”, a Done tap right after choosing the signature is ignored, so a fast double tap on Next no longer skips placing it. The founder asked for these two fixes on 2026-11-09.

**Why:** A tester saved a signed contract to Downloads and was warned the changes would be lost; a fast double tap skipped placing the signature.

**Status:** Decided; not verified on a device

### D-520 — Convert to Excel keeps pictures and no longer turns a form into one big grid

The founder confirmed on 2026-11-10 that Excel keeps the whole page, not only tables. Convert to Excel now runs the layout model and keeps pictures, cut from the user’s own copy and placed in the sheet, which can be deleted. A ruled form whose top rows are label boxes becomes text, and only its data table stays a table. Not done: pictures in an imported workbook are lost when it is edited and rebuilt.

**Why:** Without the layout model Excel did not know where a figure was, so charts were lost and one form turned into a grid.

**Status:** Decided; not verified on a device

### D-521 — Convert to Excel writes font sizes and bold

Convert to Excel writes font sizes and bold, so titles and fine print no longer all come out at the same size. Sizes follow line height as in Word, and a table gets one size for its cells. Bold is judged from stroke thickness, per text block and per table row. The founder raised it on 2026-11-10.

**Why:** The Excel writer used one font size for every cell, so titles and fine print looked the same.

**Status:** Decided; not verified on a device

### D-522 — Convert to Excel keeps two text columns side by side

Convert to Excel keeps two text columns side by side, grouping loose text the way Word does and placing text, pictures and tables in matching column ranges. Text beside a table is merged over rows so the table rows do not grow tall. Not done: a left-column paragraph with nothing beside it on the right is written full width. The founder raised it on 2026-11-10.

**Why:** Two-column pages are common in CVs, papers and manuals, and Excel had no place for the column detection Word already had.

**Status:** Decided; not verified on a device

### D-523 — The saved Excel sidecar is now version 3, and old ones open unchanged

The saved Excel sidecar moves to version 3, with new optional fields for sizes, bold, column ranges, bands and pictures. Version 2 files still open and are laid out and written exactly as before, so nothing is lost. Other versions are still refused.

**Why:** A format change needs a migration, so saved files from before keep opening.

**Status:** Decided

### D-524 — Convert to Word keeps a figure whose layout-model score is split over several classes

Convert to Word keeps a figure whose score the layout model splits over several classes, such as a chart detected as both chart and image. The figure is kept when its combined score is high enough and it holds no recognized text, so no text is swallowed. Small tables that together cover most of a picture no longer crop it as a picture. Not checked on the phone. (The founder, 2026-11-10.)

**Why:** Scanned and digital pages lost their figure in Word because each class alone scored below the cut-off.

**Status:** Decided

### D-525 — Word export preserves independent header fields and the horizontal space of text and tables

Word export now starts a label-and-value field on its own paragraph, lets the last column of a side-by-side row borrow spare space to its right for one short line, and keeps a table’s source horizontal offset as its indent. The founder asked for these fixes on 2026-11-10 after an English invoice name wrapped and receipt tables shifted left.

**Why:** The defects already existed in the baseline, and the fix adds to the existing reconstruction rather than replacing it.

**Status:** Decided

**Changed later by:** D-527.

### D-527 — Word cell padding matches its text-width budget, and a short centered heading may use spare space in the last layout column

Word tables now write explicit cell margins that match the width calculation, so tight headers no longer wrap. A short centered heading in the last column may use spare space to its right, while multi-line or right-aligned headings keep their previous width. The founder asked for this on 2026-11-11. Changes D-525.

**Why:** Table cells rendered wider than the writer assumed, and short Chinese headings wrapped because their boxes excluded the cell padding.

**Status:** Decided

### D-528 — Non-dense Word pages keep proven prose columns continuous and infer alignment inside each column

Non-dense Word pages keep two-column prose in one column scope, so isolated body fragments no longer become full-width paragraphs. Alignment is inferred within each column, so right-column titles no longer centre on the page. A spanning block or a changed column boundary ends the scope. Dense pages keep the old path. The founder asked for this on 2026-11-11.

**Why:** Local vertical bands let body fragments go full width, and page-relative alignment centred right-column titles.

**Status:** Decided

### D-529 — Word reconnects proven OCR paragraph fragments and numeric range continuations without changing unrelated paragraphs

Word reconnects paragraph fragments that OCR split across model regions, and treats a bare page-range tail after a numeric range as a continuation, not a new list item. Titles, field columns, real paragraph gaps and indents are kept, and dense pages keep the existing path. The founder asked for this on 2026-11-11.

**Why:** Model-region boundaries stranded payment tails and first or last lines, and a bare range tail looked like a new list item.

**Status:** Decided

### D-530 — Recover an unlettered figure corroborated by three nearly identical model boxes

Word recovers an unlettered figure when three nearly identical model boxes of different image-like classes agree on it, which a single score would miss. A recovered figure cannot replace an existing picture and is dropped if any recognized text lies inside it. Excel output is unchanged. The founder requested it on 2026-11-11.

**Why:** The general image cut-off could not be lowered without admitting unsupported detections, so a narrower corroboration path was added.

**Status:** Decided

### D-531 — Word protects confirmed captioned figures before table and barcode detection

Word protects a confirmed, captioned figure before table and barcode detection: its internal labels and arrows stay in the picture, and its caption stays editable text. The check runs on a masked copy, and if any protected figure would be lost, the page falls back to the original result. The founder requested this trial on 2026-11-11, prioritizing no regressions.

**Why:** Figure labels are evidence inside a picture, not independent prose or a data table, so splitting them out was wrong.

**Status:** Decided

**Changed later by:** D-533.

### D-532 — Word rejects sparse layout grids and recovers bounded table rows

Word rejects sparse layout grids that are mostly empty, such as decorative frames, and returns them to editable text. Real two-row signature tables and repeated sparse data rows remain tables. Three or more aligned columns of names or status text may form a borderless table inside a layout-model table region, but the model alone never creates a table. The founder requested these fixes on 2026-11-12.

**Why:** Decorative frames were accepted as data grids, while weak real table rules left owners and dates as separate paragraphs.

**Status:** Decided

### D-533 — Word preserves confirmed graphics and source paper geometry

Word keeps confirmed graphics: a large illustration is no longer rejected just for covering half a page, and missing barcodes are recovered from separate edge clusters. Each page carries its own paper size and margins, so exports follow the source page. Rotated table text stays editable. Expands D-531. The founder requested these fixes on 2026-11-12 and selected Node and corpus validation only.

**Status:** Decided

### D-534 — Word may read the selected digital PDF's original drawing operations locally

Word may read a selected digital PDF’s original drawing operations on the device, so vector art survives while body text stays editable. Scanned pages and ambiguous raster images still use OCR, and no cloud access is added. The founder approved this input on 2026-11-12. Its first drawing layer is superseded by D-535.

**Why:** Original graphics cannot be recovered reliably from OCR and layout alone, and copying a photographed page would overlap editable text.

**Status:** Decided

**Changed later by:** D-535.

### D-535 — Word graphics follow editable text flow

Revises D-534. Word places confirmed PDF figures in the normal text flow: they are cropped separately, and paragraphs and tables are built around them, so pictures no longer overlap body text. Only a verified page decoration may stay fixed behind content. The founder reported the overlaps on 2026-11-13.

**Why:** Fixed source drawings overlapped reflowed body text, and short form dividers split labels into wrong cells.

**Status:** Decided

### D-537 — Future periods and "today" in date comparisons

(built at the founder's request of 2026-11-14 in conversation: kernel gaps first; the design details were chosen by the implementing agent and were not individually confirmed by the founder). `PERIODS` gains `next7days`, `next30days`, `next90days`, each today … today + N − 1 (like the last-N-days periods they include today, and follow Settings → Date for the day start). `gt` / `lt` on a date, datetime or system field accept `"today"`, resolved to the logical today at evaluation, so "overdue" is `lt today` without a formula. They are filter periods only; the page period block (`PAGE_PERIODS`) is unchanged. The comparison with the previous period uses the N days before. The visa-docs sample's My IDs page shows a count of documents expiring within 30 days. Additive enum values and a new accepted value: no schema version bump or migration, old configs validate unchanged.

**Why:** "Contracts, warranties and IDs expiring soon" and "overdue" were only reachable through a formula detour.

**Status:** Implemented; unit tests and Haiku evals KG1, KG2 pass; not seen on a simulator or device.
