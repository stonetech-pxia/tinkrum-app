# Decisions D-007 to D-095

One heading per decision: what was decided, why, and its status. The exact rules are in the code, its tests and `docs/agent/`. How this log is organized: [DECISIONS.md](../DECISIONS.md).

### D-007 — No web support for now

No web support; the web-related dependencies in the template are kept for now

**Why:** §15: the launch platforms are iOS / Android; removing the dependencies could affect Expo Router, with very little benefit

**Status:** Decided

### D-008 — On-device SQLite is the only source of truth

In M1/M2 the **on-device SQLite** is the only source of truth

**Why:** §5.4; a transaction guarantees the baseRevision check and the write are atomic

**Status:** Decided

### D-009 — Changes use semantic operations, not JSON Patch

Modifications use **semantic operations**, not JSON Patch

**Why:** §7D; makes it easier to check permissions and generate change descriptions, and suits model generation better

**Status:** Decided

### D-010 — PDFs are processed on the phone with pdf-lib

PDFs are processed **locally on the phone** with pdf-lib

**Why:** §5.4; no server needed, runs in Expo Go

**Status:** Decided

### D-011 — License is AGPL-3.0-only with a dependency license check

License **AGPL-3.0-only**; dependencies must be AGPL-compatible, checked with `npm run check:licenses`

**Why:** Decided by the founder (§15); the script scans every installed dependency and fails on any license outside the allow list. At M0 all 1000 dependencies passed; after M2 introduced pdf-lib, `pako` (MIT AND Zlib, GPL-compatible) was added and put on the allow list

**Status:** Decided

### D-012 — Target market is overseas

Target market: **overseas**

**Why:** Decided by the founder (§15); the default candidate for M3 is Supabase

**Status:** Decided

### D-014 — Workflow steps pass data through four fixed slots

Superseded by D-060 (schemaVersion 5). The text of this decision was deleted on 2026-11-22.

### D-017 — Mock AI rejects a sentence if any clause is not understood

The mock AI splits the input into clauses at punctuation; if any clause is not understood, the whole sentence is rejected; a clause that is already the target state produces no change

**Why:** §7F: no speculative changes are generated

**Status:** Decided

### D-018 — A version counts as rendered after one successful render

Definition of "render succeeded": after a commit, the shell renders once with the new version (not caught by an ErrorBoundary) and that counts as success; on failure it falls back to the config of the last successful render, and after 3 consecutive failures it stops and shows an error

**Why:** §4: success is shown only after the change is persisted, re-read and rendered successfully

**Status:** Decided

### D-019 — User files are stored as assets by id and name

User files are stored in the app documents directory as `assets/<id>/<file name>`; the database stores only the relative path; if the name is taken, a sequence number is appended to the display name

**Why:** Fully separate from config versions (§7G); the right name shows when sharing by file name; relative paths are unaffected by iOS container path changes

**Status:** Decided

### D-020 — Workflow parameters are parsed again before each run

Before a workflow runs, the parameters are parsed again against the action contract; pdf.merge checks the AssetGrant before reading each file

**Why:** Defense in depth: although the config has been validated, the execution layer still does not trust its input

**Status:** Decided

### D-021 — Accept pdf-lib as an unmaintained but usable dependency

Risk note: pdf-lib was last released in 2022 (MIT; feature-stable but unmaintained)

**Why:** Meets the merge need for now; if compatibility or security problems appear, the replacement is limited to `packages/tool-pdf`

**Status:** Decided

### D-023 — Plan is returned as validated JSON text, not structured output

No structured output (JSON Schema constrained decoding); the model replies with the core `Plan` as JSON text, and the server validates it strictly and corrects at most once

**Why:** There are many kinds of operations, and the generated constraint grammar exceeds the API limit (`compiled grammar is too large`); text JSON + validation scored 22/22 on all 3 models in the eval

**Status:** Decided

### D-024 — Opus and Sonnet requests enable the refusal fallback

Opus / Sonnet requests turn on the server-side refusal fallback by default (`fallbacks: "default"`); Haiku 5.5 does not support it, so it is off

**Why:** Official recommendation; on a refusal it retries automatically with another model, and returns a refusal only if that fails

**Status:** Decided

### D-025 — Plan service listens locally with counted rate limits

Until accounts go live, the plan service listens on the local machine only, with server-side counted rate limits (10 per minute, 200 per day, adjustable by environment variables)

**Why:** No public exposure before login authentication exists, so others cannot use up the quota

**Status:** Decided

### D-026 — Service outage never falls back to the mock AI

When the service is unavailable the app clearly says "No changes were made", and does not silently fall back to the mock

**Why:** Avoids the user thinking the result came from the real AI

**Status:** Decided

### D-028 — Official app also offers the user's own API key

The official app also offers "use your own Claude API key" (option B), with the hosted AI still the default

**Why:** Decided by the founder. Target users will hardly ever apply for a key, and users willing to tinker can already compile from the AGPL source

**Status:** Decided

**Changed later by:** D-new-simplify-ai-app-onboarding-7c8b13-1.

### D-029 — User's own API key is stored in secure storage

The user's key is stored in `expo-secure-store` (`WHEN_UNLOCKED_THIS_DEVICE_ONLY`: not migrated with backups) and is sent only to api.anthropic.com; the UI shows only the last four characters; "Test connection" uses the Models API and consumes no tokens

**Why:** The user's own key stays on the user's own device; the rule "no keys on the phone" refers to our key

**Status:** Decided

### D-031 — Settings is the only protected element of navigation

The only protected element is **Settings**: it must be in the navigation bar or a floating button; the Settings page is always provided by the core with the entries "Change this app", "Change history" and "Tools". AI change, history and tools can all be removed from the navigation bar and floating buttons; the tool page always has an AI entry at the top right

**Why:** Decided by the founder (2026-10-22): "Everything except Settings can be removed from the navigation bar; Settings keeps AI change and history so there is always a way back." The tools entry was added on top of that: otherwise, once "Tools" and "Add tools" are removed, tools could no longer be installed / uninstalled by hand

**Status:** Decided

### D-032 — Default style is Clay with Sora and Karla fonts

The default style is the Clay look: sand background, cream cards, terracotta primary, sage secondary, Sora headings and Karla body text, light by default with a warm brown dark mode. Fonts use static weights. The founder decided this on 2026-10-22.

**Why:** Variable fonts render unreliably by weight on React Native.

**Status:** Decided

### D-033 — schemaVersion 2 turns the theme into a token allow-list

The theme becomes an allow-list of style tokens such as colors, fonts, sizes, corner radius, density, card style and navigation style. Pages can be created, deleted and given icons, and new components are added. Old configs migrate, keeping the primary color and appearance, and Settings is restored if missing. No arbitrary code is allowed.

**Why:** The founder asked that style, layout, components and pages all be changeable, still without running arbitrary code.

**Status:** Decided

### D-034 — Groups nest one level and hold at most 12 children

Groups have only one level (a group cannot contain another group), at most 12 child components; grids have 2 or 3 columns

**Why:** Covers common layouts such as rows and grids, while keeping validation, change descriptions and model output simple

**Status:** Decided

### D-035 — Validator enforces 4.5:1 body text contrast

The validator checks body-text contrast: text must be at least 4.5:1 (WCAG AA) on both the background and cards, and with "follow system" both light and dark are checked. Text on the primary color automatically picks black or white; when the primary color is not clear enough on cards, it is automatically darkened / lightened when used as text

**Why:** Stops the AI from making the UI unreadable, which would leave the user unable to find Settings or undo

**Status:** Decided

### D-036 — The AI only changes the interface

it cannot read, write, delete or aggregate user records. Such requests (「记一笔」 ("log an expense"), 「删掉上个月的账」 ("delete last month's entries"), 「这个月花了多少」 ("how much did I spend this month")) are refused with the new refusal reason `userData`

**Why:** Decided by the founder (2026-10-22): "For now it can't write on my behalf, the AI only changes the interface; we must guarantee the AI can never read user data". For how the guarantee works see DATA_DESIGN.md §10

**Status:** Decided

### D-037 — Deleted records are kept for 30 days

Deleting a record is a soft delete: it can be undone from the banner, Settings → Data → Recently deleted keeps it for 30 days, and on launch anything older than 30 days is purged

**Why:** Decided by the founder (as suggested)

**Status:** Decided

### D-038 — Fields convert only between compatible types

A field can only be converted between compatible types (text ↔ long text, number ↔ amount); in all other cases create a new field and move the old one out (the values in the records are kept)

**Why:** Decided by the founder (as suggested)

**Status:** Decided

### D-039 — AI can remove a table from the interface, keeping records

The AI can move a table out of the interface (`removeCollection`, together with the components that show it); the records stay in Settings → Data and come back when a version that contains this table is restored; permanent deletion can only be done by the user, with manual confirmation in Settings → Data

**Why:** Decided by the founder

**Status:** Decided

### D-040 — Mock AI has four built-in templates

The mock AI has four built-in templates: bookkeeping, to-do, reading list and notes (`core/src/templates.ts`); the eval also uses them to prepare the initial state

**Why:** Decided by the founder (as suggested)

**Status:** Decided

### D-041 — Every table can be exported as CSV

Every table can be exported as CSV (with a BOM so Excel opens Chinese text directly), sent through the system share sheet; the exported file lives in the cache directory and does not become a user file

**Why:** Decided by the founder (as suggested)

**Status:** Decided

### D-042 — Only structure, not record content, is sent to the AI

Table names, field names and option labels are sent to the AI as interface structure; record content is never sent. The Settings → Data page states this

**Why:** Decided by the founder (as suggested)

**Status:** Decided

### D-043 — Filtering and statistics run in memory up to 10,000 records

Filtering, sorting and statistics are computed in memory with pure functions in `core` (limit of 10,000 per table); if records grow very numerous, switch to SQLite `json_extract`

**Why:** Shares the same logic with the tests, so results are identical; performance is sufficient up to 10,000 records

**Status:** Decided

### D-044 — Rich text supports a Markdown subset only

Rich text: text (≤ 1500 characters) and callouts (≤ 600 characters) support a Markdown subset: bold, italic, links, bulleted / numbered lists, blank-line paragraphs; HTML, headings and inline images are not supported. It is parsed into data and mapped to native text styles

**Why:** Lets the AI write structured explanations without introducing any executable content

**Status:** Decided

### D-045 — Links allowed only for https and mailto, with confirmation

Links are allowed only with `https://` and `mailto:`; the validator rejects other protocols. When the user taps a link, a dialog first shows the target domain or email address, and the link opens only after confirmation

**Why:** Prevents phishing, `javascript:` and local-file links generated by the AI or placed by mistake by the user

**Status:** Decided

### D-046 — Image slots are filled by the user from the photo picker

The AI can place an empty image slot and set its shape and hint text, but cannot see or choose the photo. The user taps the slot and picks a photo from the system picker, stored as a user file that the config references only by a random ID. Setting, replacing or removing a photo can be undone.

**Why:** The AI must not read user data, and photos belong to the user.

**Status:** Decided

### D-047 — Selected photos are re-encoded as JPEG without metadata

The selected photo is re-encoded as JPEG with a longest side of 2048 pixels (`expo-image-manipulator`): a uniform format (Android cannot display HEIC), smaller size, and metadata such as location removed (measured on the simulator: a 4032×3024, 2.7 MB HEIC became a 2048×1367, 731 KB JPEG, and the EXIF kept only orientation and dimensions)

**Why:** Privacy and storage

**Status:** Decided

### D-048 — Icons can be a built-in name or a single emoji

An icon can be a built-in icon name or a single emoji (recognized by code point range, without relying on regex Unicode properties, so it also works on Hermes)

**Why:** The built-in icons are limited; emoji cover almost every theme

**Status:** Decided

### D-049 — schemaVersion 4 adds images, emoji icons and rich text

schemaVersion 4: adds the image component, emoji icons and rich text; v3 → v4 only bumps the version number

**Why:** An older app that reads a newer config treats it as "version too new" instead of misjudging it as corrupted

**Status:** Decided

### D-050 — Photo requests always place an image slot, never text

The prompt states explicitly: when the user asks for a photo / header image / banner image, always place an empty image slot and never substitute text; multi-part requests must be completed item by item, and if one part cannot be done the whole sentence is refused

**Why:** In a simulator test Haiku turned 「横幅」 ("banner") into a text callout; after adding the rule, similar cases passed 15/15

**Status:** Decided

### D-051 — File lists show documents, not interface photos

The file list shows documents only: photos used by the interface are still user files, but they do not appear in file lists such as "Recent files"

**Why:** Decided by the founder (2026-10-22)

**Status:** Decided

### D-052 — Long-press edits become semantic operations with one undo

Long-pressing a component on an app page opens an action panel for text, color, alignment, size, moving, hiding and deleting. Each action goes through the same validation as AI changes, and Done saves the whole edit as one undoable manual-edit version. The founder requested this on 2026-10-22. Its current form is set by D-235.

**Why:** It reuses the AI change protocol, so validation, history and undo apply, and the config is never written directly.

**Status:** Decided

### D-053 — Edit mode is a toggle with arrows and drag handles

Edit mode is a toggle, entered through an Edit button or a long press. Components get drag handles and up and down arrows, hidden components stay visible but faded so they can be restored, and tapping opens the action panel. The founder confirmed the toggle on 2026-10-22. Its current form is set by D-235.

**Why:** Arrows work in every situation, and dragging is only a speed-up.

**Status:** Decided

### D-054 — Edit-mode changes stay in a draft until Done

Edit-mode changes stay in a draft until Done, which saves them as one version. Cancel discards everything after asking if there are changes, and the navigation bar is hidden while editing. The founder requested this on 2026-10-22.

**Why:** One editing session takes one history entry, so one undo returns to before the edit.

**Status:** Decided

### D-055 — Only deletion asks for confirmation in edit mode

In edit mode only deletion asks for confirmation. Color, alignment, size, hiding and moving take effect at once in the draft, and the panel stays open so options can be tried. The founder asked for confirmation before deletion.

**Why:** Deletion is the least noticeable action, while Cancel can discard all other changes at once.

**Status:** Decided

### D-056 — Editable scope covers pages, not settings or record pages

Editing covers pages in the navigation bar and standalone pages, but not Settings, the tool catalog, history, data, the AI change page or record edit pages. The panel offers only looks the renderer can show, and data components can be moved, recolored, hidden or deleted but never change records. The founder asked for this on 2026-10-22.

**Why:** The options match what the renderer can show, so no tap seems to do nothing.

**Status:** Decided

### D-057 — A null value removes an optional property

In `setComponentProps`, a value of null means removing that optional property (consistent with `setComponentStyle`), used to clear optional text such as a subtitle; the prompt is updated to say so. Haiku 5.5 eval 46/46

**Why:** When changing text, optional text can be cleared, and the AI can also "remove the subtitle"

**Status:** Decided

### D-058 — Saving keeps the edit draft and scroll position

After a version is saved the page remounts (ErrorBoundary is keyed by version), so the edit draft is kept in the store, and each page's scroll position is remembered in memory, so after saving the page stays where it was

**Why:** No jump back to the top after editing

**Status:** Decided

### D-059 — Dragging near the screen edge scrolls the page

Dragging near the top or bottom edge of the edit area scrolls the page automatically, faster nearer the edge. A long-press on a form field keeps the system text selection. The founder confirmed this on 2026-10-22.

**Why:** A long page can be dragged to its target in one go, without fighting the system's text gestures.

**Status:** Decided

### D-060 — Workflow steps pass one typed value between them

Each workflow step passes one typed value to the next, such as images, PDF, files, zip, text or records. The validator checks statically that adjacent steps connect, and the chain stays linear with no branches or loops. Changes D-014.

**Why:** Fixed slots only fit one flow, and cross-tool workflows need general type checking.

**Status:** Decided

### D-061 — A tool used alone is a workflow with one action

A tool used alone is saved as a workflow with just that one action, written into the config when the tool is installed. The user and the AI can change its settings, and it is removed with the tool and cannot be deleted separately.

**Why:** The tool page and workflows share one executor, and often-used settings can be saved.

**Status:** Decided

### D-062 — Preset workflows are copied into the config when added

Preset workflows are written in code; when the user taps "Add" on the Workflows page, the preset is copied into the config (`presetId` records the source, and it can be reset to the preset), after which it is exactly like the user's own workflow

**Why:** The config contains only the workflows the user actually uses, so the AI's prompt does not grow with the presets; presets update with the app and are not affected by restoring historical versions

**Status:** Decided; updated by D-236: presets do not need to be added

### D-063 — Run inputs are temporary files, saved only on request

Inputs and intermediate results during a run are temporary files in the cache directory, cleaned up after the run ends; only the "Save" step or "Save" on the result page makes a user file. Previously "merge PDF" also imported the selected PDFs into the file list; after the migration it no longer does

**Why:** Dozens of photos chosen for compression should not fill up "Recent files"; files stay only when the user explicitly saves

**Status:** Decided; the file room's desk lives in the documents directory, not as temporary files (D-357)

**Changed later by:** D-357.

### D-064 — Large dependencies download as packs on first use

Large dependencies such as scanning, text recognition languages and the PDF preview download as packs the first time the user needs them. The user must confirm each download in the interface, the hash is checked, and packs work offline and can be deleted in Settings. The founder asked for this.

**Why:** The founder asked that large dependencies download only when first needed.

**Status:** Decided

### D-065 — Private text in parameters is hidden from the AI

Text the user writes in workflow parameters (watermark, text stamp) is marked private in the UI metadata and replaced with a placeholder in the config sent to the AI; text the user says to the AI is used as usual

**Why:** Such text may contain personal information such as names; spec numbers (KB, pixels) are still sent

**Status:** Decided

### D-066 — Tapping Start runs a quick action immediately

Tapping Start on a workflow card runs it at once and opens a run page that shows each step's status and can be stopped. The result page offers save, share, save to Photos, print and copy.

**Why:** One tap starts the run, and the user looks at the result before deciding to save or share.

**Status:** Decided

**Changed later by:** D-362.

### D-067 — The run-time file name box shows the generated name

When the file name is asked at run time, the input box shows the name already generated from the template (for example 「报告-合并」 ("Report-merged")), and what the user edits is the final name; curly braces are stripped, so a template cannot be written here

**Why:** Ordinary users do not understand `{sourceName}`

**Status:** Decided

### D-068 — Photo date and orientation are read by a small parser

A small built-in parser reads only a photo's capture date, orientation and whether it has location, and stores nothing else from EXIF. For photos from the library, the capture time given by the picker is used directly.

**Why:** The existing library relies on features uncertain on Hermes, and only three fields are needed.

**Status:** Decided

### D-070 — Re-encoding strips EXIF, including location

Any step that re-encodes an image, such as convert, resize, compress, crop or rotate, strips all metadata including location, and its description says so. A separate Remove location step does this losslessly for JPG, and HEIC is never output by default.

**Why:** Re-encoding drops metadata anyway, and flows that must remove location show it as a visible step.

**Status:** Decided

### D-071 — Compress to a target size by quality first, then dimensions

Compress to a target size first tries the highest quality, then lowers quality, then scales the dimensions down, within a fixed number of encodes. It outputs only JPG or WebP. If the target cannot be met it reports an error with the smallest size achieved.

**Why:** Users accept quality loss before size loss, and the attempt limit keeps it fast on a phone.

**Status:** Decided

### D-072 — Single-function quick actions ask the main setting each run

A single-function workflow on a tool page asks for its main setting on every run, with common size buttons such as 240 KB or 1 MB above the input. The card lists only fixed settings.

**Why:** When a tool is used alone the need differs each time, and buttons are faster and less error-prone than typing.

**Status:** Decided

### D-073 — PDF tool 2.0 adds mixed merge, size limits and page rules

The PDF tool can merge PDFs and images together, and turn images into PDFs with page size, margins and an optional size limit. Page selection uses named rules such as odd pages or the last page, which the AI can pick without seeing content. Text the standard PDF fonts cannot write is drawn as an overlay image.

**Why:** Standard PDF fonts cannot write Chinese, Japanese or Korean, and rule-based pages let the AI change steps without touching files.

**Status:** Decided

### D-074 — Installed tools upgrade without losing user changes

Tools installed in an older version are upgraded in place: new single-function workflows and the tool-page entry are added, while workflows and pages the user changed stay as they are. The tool catalog shows Update when versions differ.

**Why:** Users should not have to reinstall a tool to get new features and lose their changes.

**Status:** Decided

### D-075 — Pack pages load inline with no network access

Pack pages load entirely offline. The page has no network access, and the app passes it only the verified pack files and the inputs for each call. It can read nothing else.

**Why:** Measured in the simulator, a PDF preview pack ran offline in seconds; Android WebView is not verified.

**Status:** Decided

### D-076 — Packs download in parallel and are verified

Packs download in parallel by file (6 at a time), and each file is verified for size and SHA-256; the text recognition pack is split into a main pack (tesseract.js + core) and 12 language packs, each downloaded separately

**Why:** The PDF preview pack has more than 180 small cmap files, and serial download takes a minute; each language model is 0.7–3 MB and the user needs only the languages they use

**Status:** Decided

### D-077 — Form filling returns only the fields the user changed

Form filling generates inputs by field type and returns only the fields the user changed, so unchanged fields are not rewritten. Text the standard fonts cannot write is flagged and blocks submission. Stop works even when a step hangs.

**Why:** Rewriting unchanged fields could introduce errors, and Stop must always work.

**Status:** Decided

### D-078 — Scan and OCR are new tools with manual corner confirmation

Scanning and text recognition are two tools. Every photo opens a four-corner adjustment screen after edge detection, and a bad shape cannot be submitted. Text recognition handles one language at a time and downloads only that language's pack.

**Why:** Edge detection drifts with clutter and uneven light, and language packs download on demand to save data.

**Status:** Decided

**Changed later by:** D-266.

### D-079 — Image compositing runs fixed step types within canvas limits

Image compositing uses a fixed set of drawing steps within canvas size limits, and anything too large is scaled down as a whole. Long stitched images are narrowed before being split. Redaction always re-encodes, and ID photos meet the size cap by lowering quality only.

**Why:** A smaller image is better than a crash, and official photo sizes cannot change.

**Status:** Decided

### D-080 — New zip, qr, text and print tools with fixed report templates

New zip, QR, text and print tools. Reports use only fixed templates (table, cards or list with totals) filled with record values on the device, and the AI can pick only the template, title and field IDs. The report tool has no workflow of its own.

**Why:** The AI does not read records, and fixed templates leave no HTML that could inject content.

**Status:** Decided

### D-081 — Presets are copied into the config and need no tool install

The built-in presets are copied into the config when added, need no tool installed first, and can be added more than once. A preset that needs a pack asks for the download the first time a run reaches that step. Reset to the preset restores the steps of the current app version.

**Why:** The user taps Add and it works, and presets update with the app while copies keep the user's changes.

**Status:** Decided

### D-082 — Workflow edit page saves one version per Save

The workflow edit page keeps changes in a draft, and Save makes one undoable version. Only steps whose types connect can be inserted, and built-in workflows can be edited but not deleted. Deleting a user workflow also removes its run card, while files are kept.

**Why:** The edit page uses the same undoable protocol as other changes, with validation in one place.

**Status:** Decided

**Changed later by:** D-362.

### D-083 — AI can build and change workflows from presets and actions

The AI can build and change workflows from presets and actions, and adds a home-page card only when asked. It can turn records into a report by supplying only the table, time range, template and field IDs. It still sees only the config and action list, never file names, text or record contents.

**Why:** The AI must never see file or record content, so it works only from the config and the action catalog.

**Status:** Decided

### D-084 — Switch to development builds

The app runs as a development build rather than in Expo Go, so native features such as Vision and the document camera work. Native projects are generated from config and not kept in git, and our own native code is a local module that uses only system frameworks.

**Why:** Native features need a development build, and generated native projects keep SDK upgrades to config changes.

**Status:** Decided

### D-085 — iOS text recognition uses Vision

On iOS, text recognition uses the system Vision framework, limited by D-269 to languages PP-OCRv6 does not handle. The action interface is unchanged, and unsupported languages report an error. The text is returned only to the app and never logged or sent to the AI.

**Why:** It is built into the system, works offline with no 9 MB download, and is clearly more accurate for Chinese.

**Status:** Decided

**Changed later by:** D-269.

### D-086 — iOS scanning uses Vision + Core Image

On iOS, scanning finds edges with document segmentation, falling back to rectangle detection when segmentation misses a page edge, then straightens the photo. Camera scanning uses the system document camera, which returns pages already straightened, so workflows work with or without it. (The founder, 2026-10-27.)

**Why:** The system document camera gives the best scanning experience, and already-straightened pages pass straight through.

**Status:** Decided

### D-087 — Android uses Google ML Kit

On Android, text recognition uses Google ML Kit with models bundled in the app, so it works offline without Google Play services. Russian still uses the tesseract pack. Camera scanning uses the ML Kit document scanner where Google Play services exists, and the plain camera otherwise. The founder decided this on 2026-10-23.

**Why:** Bundled models keep text recognition independent of Play services, and the scanning UI exists only in the Play services version.

**Status:** Decided

**Changed later by:** D-269.

### D-088 — schemaVersion 6 adds third color, dark colors and backdrop

schemaVersion 6: the theme gains a third-color override (`colors.tertiary`), dark-mode colors (`darkColors`), a page background (`backdrop`) and six card styles; v5 → v6 only bumps the version number

**Why:** Fills in the capabilities needed for preset styles (neo-brutalism, neumorphism, clay, dark neon, etc.); all are new optional items, so old data needs no change

**Status:** Decided

### D-089 — Dark-mode colors fall back from darkColors to colors to Clay

Dark-mode color order: `darkColors` → `colors` → Clay dark. An old theme that has only `colors` looks the same in dark mode as before

**Why:** Does not change how existing themes display; a preset can provide separate light and dark palettes; the contrast check covers both modes

**Status:** Decided

### D-090 — Shadow color follows the body text when the palette changes

When the background / card / text color is changed, the light-mode shadow color uses the body text color (it used to be fixed at Clay's warm brown); when the palette is not changed, the Clay shadow is still used

**Why:** A brown shadow looks dirty with a cool or neon palette; the body text color has the same hue as the theme, with the same opacity

**Status:** Decided

### D-091 — Brutal, soft and puffy card styles

Three new card styles: brutal (a border and a hard, unblurred shadow), soft (a soft two-way shadow that suits cards matching the background) and puffy (outer and inner soft shadows). They use the new-architecture box shadow, with no new dependency.

**Why:** The old shadow properties cannot make hard, multi-layer or inner shadows.

**Status:** Decided

### D-092 — Glass card uses Liquid Glass where available

The glass card style is frosted: on iOS 26 and later it uses the system Liquid Glass, on earlier iOS a blur, and on Android only a semi-transparent card with no blur. The bottom navigation bar and floating button also become glass. The founder asked for all popular styles on 2026-10-22.

**Why:** Android's blur needs the content behind it wrapped, which cannot be done for cards inside scrolling pages.

**Status:** Decided

### D-093 — Page backgrounds: gradient, aurora, glow and chrome

Page backgrounds come from a fixed list: plain, gradient, aurora, a neon glow outline, or a metallic chrome. All colors are computed from the palette and follow dark mode, and arbitrary colors and images are not allowed.

**Why:** A fixed list is easy for the AI to use, and the contrast check can cover every background.

**Status:** Decided

### D-094 — Twelve built-in style presets applied as a whole

Twelve built-in style presets can be applied as a whole: the AI replaces the whole theme in one step and can then fine-tune it. Terminal and neon are dark only, and every preset must pass the contrast check. A request for a whole style applies a preset, while a request for frosted cards changes only the card style.

**Why:** The founder chose the styles on 2026-10-22, and applying a complete tested set is steadier than assembling many tokens.

**Status:** Decided

### D-095 — Style presets can be picked by hand on the AI page

The AI page has a Pick a style row with small samples of the 12 presets, and a check mark when the theme exactly matches one. Tapping a sample fills its style sentence into the input box, and the user then taps Preview and applies or cancels. The founder asked for this during Android testing on 2026-10-23.

**Why:** The founder wanted to pick a style by hand, and filling without previewing lets the user edit the sentence.
