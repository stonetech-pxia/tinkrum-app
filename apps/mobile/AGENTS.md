## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. Before writing code that touches an Expo or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt and follow its links to the page you need; never answer from memory.

## Commands

```bash
npx expo install <package>  # ALWAYS use instead of npm add — resolves SDK-compatible versions
npx expo-doctor             # diagnose dependency and config issues
```

One test file, from the repository root: `npm run test --workspace @morph/mobile -- src/__tests__/<file>`. What must pass before a task is done is in the root `AGENTS.md` ("Tests", "Before merging").

## Navigation & Routing

- Use **Expo Router**. Routes live in `src/app/`: every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code outside `src/app/`.

## Rules

- `ios/` and `android/` are generated by prebuild and ignored by git. Never edit them by hand; configure native behavior in `app.json`, config plugins (`plugins/`) and the native modules in `modules/`.
- **Builds are local.** There is no EAS and no over-the-air update in this project. Build and install as the root `AGENTS.md` says.
- **UI comes from one place.** Colours, spacing and corner radius come from the palette (`src/renderer/theme.ts`): `palette.radius`, `palette.controlRadius` (buttons, inputs), `palette.pad`, `palette.inset`, `palette.gap`; text tones go through `textColor` in `src/renderer/style.ts`. Cards, buttons and pills come from `src/renderer/ui.tsx` (`Card`, `Button`, `Pill`, `ListRow`, …). Selectable chips use `Pill` with `selected`, `radio`, `icon` or `danger`; do not write another `Chip`. Settings rows are `RowGroup` in `src/shell/RowGroup.tsx`. All copy goes through `packages/core/src/messages/`. If what you need is missing, add it there first, then use it.
- **Overlays come from `src/renderer/Overlays.tsx`.** Use `BottomSheet` for bottom menus and forms, `Dialog` for centred prompts and progress, and `FullScreenModal` for viewers and local editors. BottomSheet and Dialog own the scrim, keyboard avoidance and safe-area spacing; FullScreenModal owns only the full-screen window, so its content keeps its own insets. Callers supply content and close callbacks. Do not add a direct `<Modal>` elsewhere. Overlay colours use `palette.scrim` / `scrimStrong`; text on a solid accent uses `palette.onAccent(colour)`.
